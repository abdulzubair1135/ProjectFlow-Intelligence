# Offline Synchronization Protocol

ProjectFlow Intelligence implements an offline-first operational model allowing desktop and mobile users to create, modify, and manage tasks and projects while disconnected from the central server.

---

## Architecture of the Sync Pipeline

```mermaid
sequenceDiagram
    participant UI as Client UI / App
    participant LocalDB as Local SQLite / Room DB
    participant Queue as Pending Sync Queue
    participant Worker as WorkManager / Background Thread
    participant Server as Spring Boot SyncService
    participant MainDB as PostgreSQL / Supabase

    UI->>LocalDB: Write Mutation (Create/Update Task)
    UI->>Queue: Enqueue SyncOperation (id, op, entity, payload, timestamp)
    Note over UI,LocalDB: Local UI updates immediately (zero latency)

    Worker->>Queue: Poll Pending Operations
    Worker->>Server: POST /api/v1/sync/push (Batch of operations)
    Server->>MainDB: Validate Versions & Apply Changes
    Server-->>Worker: SyncResponse (Applied IDs, Server Timestamps, Conflicts)
    Worker->>Queue: Remove Applied Operations
    Worker->>Server: GET /api/v1/sync/pull (Fetch delta since last sync)
    Server-->>Worker: Delta Entities
    Worker->>LocalDB: Update Local SQLite Cache
```

---

## Idempotency & Sequencing
- Each operation generated by a client receives a globally unique `UUID` and monotonically increasing `client_sequence`.
- The server checks the `sync_operations` table to guarantee that retransmitted requests are processed exactly once.
- Operations are evaluated in creation order per entity to prevent out-of-order state transitions.
